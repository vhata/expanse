## Summary

Of the 23 previously open findings, 14 close and nine remain open.
Eight additional findings bring the inventory to 17: two P2 and 15 P3.
Storage validation, atomic replacement, editor cancellation, CLI contract
tests, menu rebuilding and several packaging/documentation cleanups have
landed. The most consequential remaining defects lose updates: the daemon
saves its startup snapshot, and CLI commands save snapshots taken before
interactive input. Atomic replacement prevents partial JSON writes but
does not serialize read-modify-write operations.

Four backlog entries cover six findings. Eleven findings remain inventory
with explicit dispositions below. This PR records review evidence and
follow-up work; it contains no product fixes.

## Invariants

Confirmed at this commit:

- Store access goes through `expanse/core.py`, and the path comes from
  `$HOME`. Tests use fake or temporary homes.
- Core and CLI import no macOS-only modules.
- Loading malformed JSON, invalid UTF-8 or non-string snippet values
  raises `StoreError`; it never substitutes an empty store. CLI failures
  report the problem and leave the file unchanged when present at load.
- Saves validate the proposed store and use a flushed/fsynced temporary
  file followed by atomic replacement, retaining symlinks and permission
  bits as documented. This is file completeness, not transaction isolation
  or proof of power-loss durability.
- CLI `dump`/`get` output, including empty content and unknown names, is
  pinned by tests. Cancelled editor sessions never store null.

Required properties that remain unenforced:

- Writers must commit against current validated state and detect conflicts
  across interactive waits and concurrent processes. Reading immediately
  before writing alone still leaves a race.
- Snippet names must be safe for the two-line dump protocol, and content
  must retain its exact bytes through input/editor/clipboard paths.
- A failed daemon write must leave both disk and the displayed/copyable
  state at the last successfully committed version.
- Stores containing private snippets need restrictive creation modes.

- `daemon-saves-stale-store` — **Daemon changes erase snippets written
  elsewhere after startup.** Bug · Moved · Verified.
  - Where: `expanse/daemon.py:15`, `:68-70`, `:103-105`, `:123-130`.
  - Severity: P2.
  - With a temporary store holding `a`, construct the daemon, run a real
    CLI subprocess adding `fromcli`, then add `fromdaemon` through the
    daemon's stubbed dialogs. Both saves succeed, but `fromcli` disappears.
    A malformed external replacement after valid startup is overwritten
    too. Commit mutations against fresh validated state with conflict
    handling; retain the external file on failure.
  - Inventory: existing TODO `daemon-reloads-store`.

- `cli-interactive-save-loses-updates` — **Saving after interactive input
  overwrites changes made while the command waited.** Bug · Open · Verified.
  - Where: `expanse/cli.py:36-47` (`edit`), `:59-68` (`add`);
    `expanse/core.py:123-128` validates only the proposed store.
  - Severity: P2.
  - Replace `click.edit` with a callback that runs a real second CLI
    subprocess adding a different snippet, verifies it reached disk, then
    returns edited content. Both commands exit 0; only the edited original
    survives. An external malformed write during the wait is also replaced.
    Add has the same stale-snapshot interval while reading stdin or asking
    to overwrite. Serialize the mutation and validate current state, merge
    unrelated changes, and report same-snippet conflicts instead of silently
    replacing them; a reload alone does not close the concurrency window.
  - Review backlog: `transactional-cli-writes`.

## Suggested order of work

1. Address CLI transactions and TODO `daemon-reloads-store`; share a storage
   transaction/conflict mechanism rather than relying on atomic replacement
   or independent reloads. Exercise two writers with synchronization points
   and changes to both distinct and identical keys.
2. Make failed daemon writes roll back displayed state and handle startup
   StoreError explicitly. Test malformed external replacements too.
3. Apply input fidelity and private permissions; keep CLI contract tests
   and external chooser behavior aligned.
4. Resolve daemon operation and packaging choices with the user. The old
   entry/install helpers should not be used as a working installation path.
